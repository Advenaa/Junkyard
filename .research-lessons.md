## Critical Lessons

- **Product completeness > code quality.** 128 cycles auditing code while the dashboard couldn't add a source. Always check: can the user complete core workflows? Missing CRUD is worse than any code bug.
- **Auto-compact this file.** Every 10 cycles or if >100 lines, prune per-cycle logs and resolved finding details. They're in git history. Only keep reusable patterns.
- **Product-level audits are highest-yield.** Cycle 129 found 27 issues (2 critical) in one scan. The dashboard has functional routes that are unreachable (no nav links), forms that don't exist (Add Source), and config fields that display but aren't editable.

## Research Strategy

- **Alternate research types**: product-level → system-level → code-level. Product-level checks UI completeness, system-level traces data flows, code-level audits specific files.
- **System-level audits find integration bugs code-level misses** (config→scheduler decoupling, wiring gaps). But they produce more false positives — triage carefully.
- **New features are highest-yield audit targets.** New code always has more bugs than mature code.
- **Agent false positives need verification.** Always cross-reference new findings against prior intentional changes and CLAUDE.md design decisions.
- **Batch medium fixes efficiently.** Group by file to avoid conflicts, scale agents to match work scope.

## Recurring Bug Patterns

- **Epoch ms vs seconds mismatch** — `to_timestamp(created_at)` treats ms as seconds. Watch any new code touching `created_at`.
- **BIGINT returned as strings** — node-postgres OID 20 has no type parser. Fixed with `pg.types.setTypeParser(20, parseInt)`.
- **json_agg without ORDER BY** — non-deterministic row order. Any `result[0]` from json_agg is vulnerable.
- **Zod schema empty strings** — `z.string()` allows empty. All LLM output name/title fields need `.min(1)`.
- **console.error bypasses pino secret masking** — always use the logger for secrets.
- **Interface changes break test mocks** — query order changes, new params, extracted helpers all require mock updates.
- **Dashboard-API gaps** — Backend endpoints built but never surfaced in UI. Always cross-check server.ts routes against dashboard fetch calls.
