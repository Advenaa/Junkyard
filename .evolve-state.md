- [x] Cycle 143: Integration — reconnect() on adapter, updateTokens() on REST, loadAllTokens() merges env+DB, health endpoint, POST/DELETE trigger reload

- [x] Cycle 145: Verify end-to-end — Browser-verified with Playwright against a static preview using mocked auth/API/runtime token health. Add, disable, re-enable, and remove flows passed; screenshots captured.

Design decisions:
- Tokens encrypted at rest with AES-256-GCM (PBKDF2 key derivation)
- Encryption key from TOKEN_ENCRYPTION_KEY env var, fallback to SESSION_SECRET
- DB tokens coexist with env var tokens (env = system, DB = managed)
- Token status in DB is 'active'/'disabled' only; runtime health (connected/rate_limited/banned) tracked in-memory by Gateway adapter
- GET endpoint masks tokens (first 10 + last 4 chars)
- CLAUDE.md "no secrets in DB" exception: encrypted tokens required for UI management

## Lessons

### Critical Lessons

- **Product completeness > code quality.** 128 cycles auditing code while the dashboard couldn't add a source. Always check: can the user complete core workflows?
- **Auto-compact this file.** Every 10 cycles or if >150 lines, prune. Resolved findings and per-cycle logs are in git history.
- **Product-level audits are highest-yield.** Cycle 129 found 27 issues (2 critical) in one scan.

### Recurring Bug Patterns

- **Epoch ms vs seconds** — `to_timestamp(created_at)` treats ms as seconds. Watch new code touching `created_at`.
- **BIGINT as strings** — node-postgres OID 20 needs `pg.types.setTypeParser(20, parseInt)`.
- **json_agg without ORDER BY** — non-deterministic. Any `result[0]` from json_agg is vulnerable.
- **Zod empty strings** — `z.string()` allows empty. LLM output name/title fields need `.min(1)`.
- **console.error bypasses pino** — always use logger for secrets.
- **Dashboard-API gaps** — backend endpoints built but never surfaced in UI. Cross-check routes vs fetch calls.
- **CI health check pitfalls** — auth-required endpoints fail unauthenticated curl; health endpoints return 503 for data-level degradation, not server failure.

### Build Patterns

- Feature builds need 5-6 agents: schema, impl, integration, prompt, dashboard, test
- Always verify end-to-end after a feature build before marking done
- Structural tests (read source as string, regex match) are fragile to Prettier reformatting — use flexible patterns

### Product Decisions

- No plugin system, no event bus, no multi-agent (CLAUDE.md — killed v1)
- Discord tokens are user tokens (TOS risk, disposable accounts)
- News adapter exists but is URL-extraction based, not poll-based — skip in poll loop
- Narrative clustering shipped in Phase 1 (ahead of 2.2 schedule)

### Research Strategy

- **Rotate 4 types**: product-level → system-level → code-level → roadmap-gap
- **Agent false positives need verification.** Always cross-reference against prior changes and CLAUDE.md decisions.
- **Batch medium fixes by file** to avoid conflicts.
- **New features are highest-yield audit targets.** New code always has more bugs.
