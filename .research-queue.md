## Critical

### [SL-001] Discord channels hardcoded to empty array — no messages flow
- **Location**: `src/ingest/discord.ts:104-106`
- **Category**: integration
- **Description**: `getDiscordChannels()` always returns `[]`. Every MESSAGE_CREATE event is silently dropped because `assignedChannels` is empty. The entire Discord ingest path is broken.
- **Suggested fix**: Replace stub with DB query reading from `sources` table. Thread `pool` into the adapter factory.

### [SL-002] getLatestReport race — flash/daily/pulse delivery may silently fail
- **Location**: `src/index.ts:209-213, 236-239, 254-256`, `src/db/queries.ts:266-271`
- **Category**: data-integrity
- **Description**: After creating a report (flash/daily/pulse), the code re-queries `getLatestReport` (unfiltered `ORDER BY created_at DESC LIMIT 1`). If another report type is inserted between creation and fetch, the type guard fails and the report is never delivered. Scheduler mutexes are per-job, so flash and pulse can race.
- **Suggested fix**: Have `insertReport` return the full row (or ID). Callers use the returned report directly instead of re-querying.

## High

### [SL-003] Error count never resets on success, never triggers auto-disable
- **Location**: `src/index.ts:144-158, 358-364`
- **Category**: reliability
- **Description**: `updateSourceState` ON CONFLICT path never resets `error_count` to 0. A broken source polls every 60s indefinitely, flooding logs. `next_retry_at` column exists in schema but is never used. No auto-disable threshold.
- **Suggested fix**: Add `error_count = 0` to the ON CONFLICT UPDATE in `updateSourceState`. Add auto-disable after N consecutive errors. Use `next_retry_at` for backoff.

### [SL-004] Seeder skips alias insertion on re-seed for existing entities
- **Location**: `src/knowledge/seed.ts:107-109`
- **Category**: data-integrity
- **Description**: When entity INSERT returns rowCount=0 (already exists), `continue` skips alias insertion entirely. Re-seeding can never add new aliases for existing entities. If alias table is wiped or new aliases are added to static lists, they won't be populated.
- **Suggested fix**: Remove the `continue`. Always fetch the entity ID and proceed with alias inserts (which already have ON CONFLICT DO NOTHING).

### [SL-005] IP extraction mismatch between session creation and validation
- **Location**: `src/auth/discord-oauth.ts:197-199`, `src/auth/middleware.ts:30`
- **Category**: security
- **Description**: OAuth callback manually parses `x-forwarded-for`, but middleware uses `request.ip` (which ignores x-forwarded-for without `trustProxy`). Behind a reverse proxy, stored IP ≠ validated IP, defeating IP tracking.
- **Suggested fix**: Add `trustProxy: true` to Fastify config. Remove manual x-forwarded-for parsing.

## Medium

### [SL-006] Flash/pulse duplicate guard runs AFTER LLM call — wasted tokens
- **Location**: `src/process/synthesize.ts:469-479`, `src/process/pulse.ts:358-363`
- **Category**: performance
- **Description**: Both check for existing report after the expensive LLM call. If duplicate exists, tokens are wasted. Daily path correctly checks before LLM call.
- **Suggested fix**: Move duplicate guard before the LLM call in both functions.

### [SL-007] UA exact-match session invalidation too aggressive
- **Location**: `src/auth/sessions.ts:97-109`
- **Category**: reliability
- **Description**: Browser auto-updates change UA string, causing immediate session invalidation and forced re-login. Virtually guaranteed over a 30-day session lifetime.
- **Suggested fix**: Compare normalized UA (browser family + OS) instead of exact string, or downgrade to IP-must-match on UA mismatch.

### [SL-008] secure:true cookie breaks local HTTP development
- **Location**: `src/auth/discord-oauth.ts:50,213`
- **Category**: reliability
- **Description**: Both `oauth_state` and `podders_session` cookies set `secure: true`. On `http://localhost`, browsers refuse to send them back, silently breaking auth.
- **Suggested fix**: Conditionally set `secure` based on `config.publicUrl?.startsWith('https')`.

### [SL-009] Admin role revocation gap
- **Location**: `src/auth/middleware.ts:48-49`
- **Category**: security
- **Description**: Middleware only overrides to grant admin (when in `ADMIN_USER_IDS`), never to revoke. If a user is removed from env var but DB row has `role = 'admin'`, they retain admin access.
- **Suggested fix**: Add downgrade path: if not in adminUserIds and DB role is admin, demote to viewer.

### [SL-010] No direct DB ping in health checks
- **Location**: `src/health.ts:262-274`
- **Category**: reliability
- **Description**: Health monitor checks pool stats but never runs a `SELECT 1` to verify DB is actually responsive. Hanging queries or disk-full Postgres would not be detected until the health endpoint itself throws.
- **Suggested fix**: Add `SELECT 1` ping as first health check with timeout.

### [SL-011] First-poll error silently lost if no source_state row exists
- **Location**: `src/index.ts:150-158`
- **Category**: data-integrity
- **Description**: Error handler runs `UPDATE source_state SET error_count = error_count + 1` but if this is the first poll and no row exists yet, UPDATE matches 0 rows. Error is silently lost.
- **Suggested fix**: Change to UPSERT: `INSERT ... ON CONFLICT DO UPDATE SET error_count = error_count + 1`.

### [SL-012] Vector cache loads after scheduler starts — chat race
- **Location**: `src/index.ts:283-285`
- **Category**: reliability
- **Description**: `vectorCache.load()` runs after `scheduler.start()`. A chat query arriving before load completes gets zero search results. Low practical probability but easy to fix.
- **Suggested fix**: Move `vectorCache.load()` before `scheduler.start()`.

### [SL-013] Narrative date window misaligned with digest schedule
- **Location**: `src/process/narratives.ts:167-179`
- **Category**: data-integrity
- **Description**: Narrative detector uses UTC midnight boundaries, but daily digest runs at configurable time/timezone (default 09:00 Asia/Jakarta = 02:00 UTC). Summaries from 00:00-02:00 UTC are excluded from narrative clustering until next day.
- **Suggested fix**: Align narrative window with configured timezone and digest time.

### [SL-014] Tier 1 alias lookup misses normalizeAlias for $-prefixed names
- **Location**: `src/knowledge/entities.ts:73`
- **Category**: data-integrity
- **Description**: Tier 1 uses `entity.name.toLowerCase()` but `normalizeAlias()` also strips leading `$`. Seeded aliases are stored without `$`, so `$ETH` lookup misses `eth` alias, pushing to unnecessary Tier 2/3.
- **Suggested fix**: Use `normalizeAlias(entity.name)` instead of `toLowerCase()` at line 73 and similar locations.

### [SL-015] CoinGecko seeding performance — 15K sequential queries
- **Location**: `src/knowledge/seed.ts:96-136`
- **Category**: performance
- **Description**: CoinGecko's /coins/list returns ~15K coins. Seeder processes each with individual INSERT + SELECT + alias INSERT in a loop. Extremely slow on first run.
- **Suggested fix**: Batch the inserts using multi-row INSERT statements.
