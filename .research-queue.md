## Critical

### [PS-001] Missing nonce wrapping in pre-summarize LLM calls
- **File**: `src/pre-summarize/index.ts:138-144`
- **Category**: security
- **Description**: Pre-summarize calls `llm.sanitizeForPrompt()` but does NOT use `llm.wrapWithNonce()`. Violates the 5-layer injection defense. Summarize stage does wrap. Attacker can inject via labeled output format.
- **Fix**: Wrap each item's content in nonce tags before batching into prompt.

## High

### [CR-001] Correlator uses 24h UTC cutoff; daily synthesis uses local-day window
- **File**: `src/process/correlate.ts:98` vs `src/process/synthesize.ts:296`
- **Category**: data-integrity
- **Description**: correlator.run() computes `Date.now() - 24h` (UTC), but daily synthesis queries summaries by local calendar day. Misaligned windows = correlations include data outside today's report, or miss data.
- **Fix**: Pass the same time window from daily synthesis into correlator.run().

### [SP-003] getTodayWindow timezone calculation fragile for DST
- **File**: `src/process/synthesize.ts:78-106`
- **Category**: logic
- **Description**: Uses offset arithmetic (add offset to UTC, extract date, subtract offset). Fails during DST transitions. Pulse.ts uses toLocaleString approach which is more robust.
- **Fix**: Switch to Intl.DateTimeFormat approach (same as pulse.ts and narratives.ts).

### [SP-004] Flash report date string misaligns with 4h data window
- **File**: `src/process/synthesize.ts:410-454`
- **Category**: data-integrity
- **Description**: Flash loads summaries from last 4h but stores under today's local date. Near midnight, 4h window crosses calendar day boundary but report date doesn't match.
- **Fix**: Use time-based duplicate check (created_at > windowStart) instead of date-based.

### [SD-003] Entity fetch after ON CONFLICT returns wrong ID in race
- **File**: `src/knowledge/entities.ts:221-237`
- **Category**: data-integrity
- **Description**: INSERT ON CONFLICT DO NOTHING then SELECT. If concurrent insert wins, SELECT returns the other process's entity ID. Aliases/mentions get linked to wrong entity.
- **Fix**: Use INSERT ... ON CONFLICT DO UPDATE SET last_seen=now RETURNING id.

### [SD-002] Race condition between entity relevance update and decay
- **File**: `src/knowledge/entities.ts:392` + `src/knowledge/decay.ts:20`
- **Category**: data-integrity
- **Description**: Entity resolution does UPDATE relevance += weight concurrently with decay's UPDATE relevance *= 0.95. No locking. Decay can overwrite a just-applied weight increment.
- **Fix**: Add FOR UPDATE lock in decay, or use atomic operations.

### [SP-001] Unbounded getSummariesByTimeWindow query (no LIMIT)
- **File**: `src/db/queries.ts:225-235`
- **Category**: performance
- **Description**: Daily/flash synthesis loads ALL summaries in time window. During high-volume periods (100+), causes memory pressure and token budget explosion. Pulse has a cap (50) but synthesize does not.
- **Fix**: Add LIMIT 200 (or similar) to query, matching the rankAndTrim downstream.

## Medium

### [T-004] Twitter adapter concurrent poll() shares mutable state
- **File**: `src/ingest/twitter.ts:80-82`
- **Category**: race-condition
- **Description**: `halted` and `rateLimitedUntil` are shared across all sourceId polls. Concurrent polls can race on rate limit state.
- **Fix**: Use per-source state map or document sequential-only usage.

### [PS-002] Pre-summarize lacks status tracking (double-processing risk)
- **File**: `src/pre-summarize/index.ts:167-172`
- **Category**: data-integrity
- **Description**: Items updated with summary content but status stays 'ready'. Next pre-summarize run re-processes already-summarized content.
- **Fix**: Add a flag or status to prevent re-processing.

### [T-007] MAX_PAGES=5 pagination silently truncates high-volume sources
- **File**: `src/ingest/twitter.ts:9, 176`
- **Category**: data-integrity
- **Description**: Max 100 tweets per poll. No warning when limit hit. Data silently lost.
- **Fix**: Log warning when pagination limit reached with has_next_page=true.

### [CR-003] N+1 query in correlator (trust weight + urgency per entity)
- **File**: `src/process/correlate.ts:129, 144`
- **Category**: performance
- **Description**: One query per source for trust_weight, one per summary for urgency. 100 entities × 3 sources = 800 queries.
- **Fix**: Batch with IN clauses.

### [SP-006] Entity names not XML-escaped in synthesis prompts
- **File**: `src/process/synthesize.ts:181-187`
- **Category**: security
- **Description**: Entity names interpolated into XML tags without escaping. Crafted entity name with `</correlated_entities>` breaks structure.
- **Fix**: Escape `<>&'"` in entity names.

### [T-009] No validation that tweet createdAt is valid ISO date
- **File**: `src/ingest/twitter.ts:46`
- **Category**: reliability
- **Description**: `new Date(tweet.createdAt).getTime()` can produce NaN. Zod validates string but not date format.
- **Fix**: Add `.datetime()` to zod schema or guard in tweetToRawItem.

### [CR-010] Trust weights not validated (can be negative or >1)
- **File**: `src/process/correlate.ts:80-87`
- **Category**: data-integrity
- **Description**: getTrustWeight returns raw DB value. No bounds check. Corrupted weight breaks shouldFlash threshold.
- **Fix**: Clamp to [0, 1].

### [T-001] BigInt overflow if tweet ID is non-numeric
- **File**: `src/ingest/twitter.ts:192`
- **Category**: data-integrity
- **Description**: `BigInt(t.id)` throws on non-numeric strings. Crashes entire poll cycle.
- **Fix**: Validate ID format before BigInt conversion or wrap in try-catch.
