## Critical

### [CL-001] midnightEpoch wrong for west-of-UTC timezones
- **Location**: `src/process/narratives.ts:139-152`
- **Category**: data-integrity
- **Description**: The function subtracts `tzHour * 3600000` from UTC midnight, which only works for UTC+ timezones. For UTC- (e.g. America/New_York at UTC-5), it returns hour 19 of the previous day, producing a result off by 24 hours. Also broken for non-whole-hour offsets (IST +5:30). Currently latent since Asia/Jakarta is UTC+7, but will break if timezone changes.
- **Suggested fix**: Use round-trip approach: format midnight in both UTC and target TZ, compute offset from the difference.

## High

### [CL-002] trustProxy: true trusts ALL upstream — rate limit bypass + IP spoofing
- **Location**: `src/server.ts:47`
- **Category**: security
- **Description**: `trustProxy: true` tells Fastify to trust x-forwarded-for from any source. On a VPS listening on 0.0.0.0, any client can spoof their IP by sending a fake x-forwarded-for header, bypassing rate limits and IP-based session tracking.
- **Suggested fix**: Set `trustProxy` to the specific proxy IP (e.g. `'127.0.0.1'` for localhost nginx, or Cloudflare IP ranges) instead of `true`.

### [CL-003] handleTokenDeath has no try/catch — DB error crashes process
- **Location**: `src/ingest/discord.ts:685`
- **Category**: reliability
- **Description**: `handleTokenDeath` calls `await reassignChannels()` which queries the DB. If the pool throws (connection timeout, etc.), the rejection is unhandled and triggers the global unhandledRejection shutdown handler, crashing the entire process.
- **Suggested fix**: Wrap reassignChannels() call in try/catch with error logging.

### [CL-004] entities.ts rows[0] accessed without length check in Tier 3
- **Location**: `src/knowledge/entities.ts:227, 264, 295`
- **Category**: reliability
- **Description**: After `INSERT ... ON CONFLICT DO NOTHING` + `SELECT`, `fetchResult.rows[0].id` is accessed without checking `rows.length`. If a concurrent DELETE occurs or normalizeAlias produces an empty string, this crashes with TypeError.
- **Suggested fix**: Add `if (fetchResult.rows.length === 0) continue;` guard at each location.

### [CL-009] Empty UA bypasses session hijack detection
- **Location**: `src/auth/sessions.ts:122`
