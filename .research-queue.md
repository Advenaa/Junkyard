## Critical

### [CH-001] Semantic search uses wrong column name — chat search broken
- **File**: `src/chat/tools.ts:61`
- **Category**: data-integrity
- **Description**: semantic_search tool selects 'content' column but summaries/reports tables use 'body'. Query returns empty results. Chat semantic search is effectively non-functional.
- **Fix**: Change column name from 'content' to 'body'.

### [CF-002] items.status 'failed' not in CHECK constraint — writes crash
- **File**: `src/db/migrations.ts:298` (CHECK constraint), `src/process/summarize.ts` (writes 'failed')
- **Category**: data-integrity
- **Description**: Summarizer writes status='failed' for oversized items but Migration 5 CHECK only allows ('ready','filtered','processing','processed'). This crashes with constraint violation.
- **Fix**: Add 'failed' to the CHECK constraint in a new migration.

## High

### [DB-001] Dashboard not built by npm run build
- **File**: `package.json:10`
- **Category**: deployment
- **Description**: Root build script only runs `tsc`, not Vite dashboard build. Production deploy has no frontend.
- **Fix**: Update build script: `"build": "tsc && cd dashboard && npm run build && cd .."`.

### [CH-002] Token usage counted multiple times per tool round
- **File**: `src/chat/handler.ts:243-245`
- **Category**: data-integrity
- **Description**: Token tracking inside tool-execution loop counts entire accumulated message history each round. 5 rounds = historical tokens counted 5x. Users hit 100k daily limit prematurely.
- **Fix**: Track only new tokens per round, not re-count history.

### [CH-003] No error handling for LLM failures in chat handler
- **File**: `src/chat/handler.ts:234-240`
- **Category**: reliability
- **Description**: LLMHaltedError and ContextLengthExceededError propagate uncaught to Fastify global handler → generic 500. No user-friendly message.
- **Fix**: Wrap llm.call() in try-catch, return friendly messages for known error types.

### [CF-015] API_KEY and SESSION_SECRET not persisted on auto-generate
- **File**: `src/config.ts:74-84`
- **Category**: deployment
- **Description**: Auto-generated API_KEY and SESSION_SECRET are ephemeral. Server restart generates new values → all existing sessions and API tokens invalidated silently.
- **Fix**: Log a FATAL-level warning on startup if not set in .env. Consider writing to app_config table for persistence.

### [SV-001] Missing input validation on POST /api/v1/sources
- **File**: `src/server.ts:120-139`
- **Category**: input-validation
- **Description**: POST /api/v1/sources accepts body without Fastify JSON Schema. No enum validation for source type, no format check for sourceId, no length cap on label.
- **Fix**: Add Fastify JSON Schema with source enum, sourceId maxLength, label maxLength.

## Medium

### [DL-001] No idempotency guard on delivery — duplicate Discord posts
- **File**: `src/deliver/webhook.ts:283-331`
- **Category**: data-integrity
- **Description**: deliver() doesn't check delivery_status before posting. Same report can be delivered twice (e.g., catch-up race).
- **Fix**: Check delivery_status='delivered' before HTTP POST, return early if already delivered.

### [DL-007] Alert webhook has no retry logic
- **File**: `src/health.ts:253-292`
- **Category**: reliability
- **Description**: Health alert webhook fires once with no retry. Critical alerts can be silently lost on transient network failure.
- **Fix**: Add 1-2 retry attempts with backoff.

### [CF-009] Pool not closed on migration crash before process.exit
- **File**: `src/index.ts:47-54`
- **Category**: reliability
- **Description**: Migration failure calls process.exit(1) without pool.end(). Leaves DB connections hanging.
- **Fix**: Add pool.end() in catch block before process.exit.

### [DB-005] Missing Cache-Control headers for dashboard assets
- **File**: `src/server.ts:64-74`
- **Category**: performance
- **Description**: No Cache-Control headers. Hash-named assets should be immutable, index.html should be no-cache.
- **Fix**: Add conditional Cache-Control in onSend hook based on URL path.

### [DB-003] SPA catch-all serves index.html for missing static assets
- **File**: `src/server.ts:254-260`
- **Category**: reliability
- **Description**: Missing .js/.css files get index.html instead of 404. Breaks browser resource loading silently.
- **Fix**: Check file extension in catch-all, return 404 for known asset types.

### [DB-008] PUBLIC_URL not enforced when Discord OAuth enabled
- **File**: `src/auth/discord-oauth.ts:39-42`
- **Category**: deployment
- **Description**: OAuth redirects to undefined/api/v1/auth/discord/callback when PUBLIC_URL not set. Silent failure.
- **Fix**: Throw at startup if discordClientId set but publicUrl missing.

### [CH-008] Token budget resets on restart (in-memory only)
- **File**: `src/chat/handler.ts:127-149`
- **Category**: reliability
- **Description**: User daily token budgets stored in-memory Map. Restart resets all limits.
- **Fix**: Persist to llm_usage table or app_config, query on request.

### [DL-011] Catch-up daily delivery can race with scheduled delivery
- **File**: `src/index.ts:282-310`
- **Category**: data-integrity
- **Description**: Health check catch-up creates+delivers daily report independently of onDaily(). Both can fire in 5-minute window → duplicate delivery possible.
- **Fix**: Add delivery_status check before deliver() call (same as DL-001).
