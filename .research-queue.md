## Medium

### [SL-007] UA exact-match session invalidation too aggressive
- **Location**: `src/auth/sessions.ts:97-109`
- **Category**: reliability
- **Description**: Browser auto-updates change UA string, causing immediate session invalidation and forced re-login. Virtually guaranteed over a 30-day session lifetime.
- **Suggested fix**: Compare normalized UA (browser family + OS) instead of exact string, or downgrade to IP-must-match on UA mismatch.

### [SL-008] secure:true cookie breaks local HTTP development
- **Location**: `src/auth/discord-oauth.ts:50,213`
- **Category**: reliability
- **Description**: Both `oauth_state` and `podders_session` cookies set `secure: true`. On `http://localhost`, browsers refuse to send them back, silently breaking auth.
- **Suggested fix**: Conditionally set `secure` based on `config.publicUrl?.startsWith('https')`.

### [SL-009] Admin role revocation gap
- **Location**: `src/auth/middleware.ts:48-49`
- **Category**: security
- **Description**: Middleware only overrides to grant admin (when in `ADMIN_USER_IDS`), never to revoke. If a user is removed from env var but DB row has `role = 'admin'`, they retain admin access.
- **Suggested fix**: Add downgrade path: if not in adminUserIds and DB role is admin, demote to viewer.

### [SL-010] No direct DB ping in health checks
- **Location**: `src/health.ts:262-274`
- **Category**: reliability
- **Description**: Health monitor checks pool stats but never runs a `SELECT 1` to verify DB is actually responsive. Hanging queries or disk-full Postgres would not be detected until the health endpoint itself throws.
- **Suggested fix**: Add `SELECT 1` ping as first health check with timeout.

### [SL-013] Narrative date window misaligned with digest schedule
- **Location**: `src/process/narratives.ts:167-179`
- **Category**: data-integrity
- **Description**: Narrative detector uses UTC midnight boundaries, but daily digest runs at configurable time/timezone (default 09:00 Asia/Jakarta = 02:00 UTC). Summaries from 00:00-02:00 UTC are excluded from narrative clustering until next day.
- **Suggested fix**: Align narrative window with configured timezone and digest time.

### [SL-014] Tier 1 alias lookup misses normalizeAlias for $-prefixed names
- **Location**: `src/knowledge/entities.ts:73`
- **Category**: data-integrity
- **Description**: Tier 1 uses `entity.name.toLowerCase()` but `normalizeAlias()` also strips leading `$`. Seeded aliases are stored without `$`, so `$ETH` lookup misses `eth` alias, pushing to unnecessary Tier 2/3.
- **Suggested fix**: Use `normalizeAlias(entity.name)` instead of `toLowerCase()` at line 73 and similar locations.

### [SL-015] CoinGecko seeding performance — 15K sequential queries
- **Location**: `src/knowledge/seed.ts:96-136`
- **Category**: performance
- **Description**: CoinGecko's /coins/list returns ~15K coins. Seeder processes each with individual INSERT + SELECT + alias INSERT in a loop. Extremely slow on first run.
- **Suggested fix**: Batch the inserts using multi-row INSERT statements.

### [SL-016] Duplicate SessionManager instances in server + OAuth
- **Location**: `src/server.ts:45`, `src/auth/discord-oauth.ts:35`
- **Category**: reliability
- **Description**: Two separate SessionManager instances created — one in server.ts (for middleware), one in discord-oauth.ts (for create/delete). Functionally identical since stateless, but confusing and wasteful.
- **Suggested fix**: Pass sessionManager from server.ts into registerOAuthRoutes.
